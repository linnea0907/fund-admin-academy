## 二、AI Tutor 规划（后续版本，不开发页面/不调 API/不建库）

### 四种模式
- **Explain**：按框架讲解概念与判断路径。
- **Challenge Me**：出题考测并反馈。
- **Case Mode**：基于案例库做情景分析。
- **Review My Answer**：评阅用户答案。

### 答案评分维度
| 维度 | 权重 |
| --- | --- |
| Issue spotting（识别问题点） | 25% |
| Rule and framework（规则与框架） | 25% |
| Operational steps（操作步骤） | 25% |
| Risk awareness（风险意识） | 15% |
| Clarity（表达清晰） | 10% |

### 优先追问（引导而非直接给结论）
1. 哪个主体有权作出决定？
2. 哪份文件支持判断？
3. 还有什么信息尚待确认？
4. 不同司法辖区是否改变结论？
5. Admin 应执行、暂停还是升级？

### 硬性边界（AI Tutor 不得）
1. 在信息不足时给出确定性监管结论。
2. 编造费用、期限、监管表格或申报程序。
3. 把 2024 年 7 月资料描述为当前自动有效。
4. 替代 MLRO 决定是否提交可疑活动报告。
5. 替代基金运营者批准估值或接纳投资者。
6. 将输出描述为法律、税务或监管意见。

## 三、数据扩展预留（本轮已实现于类型与数据层）

`Lesson.meta` 字段已加入类型并随 6 讲数据落值，UI 不强展示：

- `sourceBasis` — 内容依据
- `contentVersion` — 内容版本
- `reviewedAt` — 复核日期
- `timeSensitive` — 时点性信息清单
- `documentsToCheck` — 办理时应核对文件
- `escalationTriggers` — 升级触发点

## 四、与 V1 的兼容约定

- 课程中心只渲染 `lessons` 数组内存在的课程；规划课程不产生卡片。
- 案例库、AI Tutor 均不在 V1 页面暴露入口。
