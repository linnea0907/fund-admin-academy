# 信息架构守则 · Subtraction First（先减法后加法）

> 适用范围：**首页 / 左侧导航 / 全站信息架构**。
> 定稿人：Lu（2026-09-18）　｜　性质：**硬约束**，非建议。
> 与 `docs/BACKLOG.md` 的关系：BACKLOG 管「要做什么」，本文件管「允许怎么做」。

---

## 1. 规则本体

> **Rule: Subtraction First（先减法后加法）**

任何涉及首页、导航、信息架构的改动，按以下**固定顺序**执行，不得跳步：

| 顺序 | 动作 | 强制要求 |
| --- | --- | --- |
| **①** | **优先删除无价值内容** | 先问「这块能不能删」。删得掉就不进入 ②。 |
| **②** | **其次调整现有模块** | 能在既有模块内解决（改文案 / 调层级 / 换聚合口径）就不进入 ③。 |
| **③** | **最后新增模块** | 新增是兜底手段，不是首选手段。 |

**新增模块必须证明现有模块无法解决问题** —— 举证责任在「想加的人」（含 AI），不在「想删的人」。

## 2. 四条硬约束

1. **左侧导航已有功能，不得在首页重复展示**。
   知识检索 / 案例库 / 术语库 / 实务工具包 / 设置等，一律只从左侧导航进入。
2. **首页默认只服务一个核心目标：继续学习**。
   首页 = 学习驾驶舱（Learning Dashboard），不是知识平台宣传页、不是功能目录、不是数据看板。
3. **首页板块存在「白名单」**，新增板块即等同于修改白名单，须显式申报（见 §4）。
4. **删除优先于保留**：判断不了价值的内容，默认删或移出首页（可移到 `/settings` 等低频承载页），
   而不是「先放着」。

## 3. 首页改版必答三问（缺一不可）

任何首页改版（含 AI 自主发起的重构），交付时必须**显式回答**：

1. **新增了什么？** —— 逐项列出，并说明各自替代了哪个被删/被改的模块。
2. **删除了什么？** —— 逐项列出；**若删除项为 0，属于高风险信号，需额外解释**。
3. **为什么不能只删除而必须新增？** —— 说明「仅删除」会导致什么具体问题（信息缺失 / 用户无法完成任务），
   并说明为什么无法通过「②调整现有模块」解决。

> 只答「新增了什么」不答后两问的改版，一律视为**违反本守则**。

| # | 板块 | 是否服务「继续学习」 | 说明 |

**白名单之外的一切内容，默认不属于首页。** 需要加回时必须走 §3 三问 + 白名单显式变更。

- 知识检索（首页搜索框）→ 能力保留在 `/search`（含 `?q=` / `?scope=` 深链）
- 知识资产（7 项全站统计）→ 管理员视角，非学习目标
- 快捷入口（6 张卡）→ 与左侧导航职责重复
- 学习路线（9 项编号一览）→ 课程中心已承载

## 5. 改版前自检清单

动手前逐条打勾，任一条为「否」则回到上一步：

- [ ] 我**先**尝试了删除，而不是先设计新模块？
- [ ] 我尝试了在**现有模块内**解决（改文案 / 调口径 / 调层级）？
- [ ] 新增的每一块，都证明了「现有模块无法解决」？
- [ ] 新增内容不是左侧导航已有功能的重复展示？
- [ ] 新增内容直接服务于「继续学习」这一核心目标？
- [ ] 我能回答 §3 的三问，且删除项不为 0？
- [ ] 删除是**真删或迁移**，不是「先留着」？

## 6. 判定依据（为什么这条规则是硬的）

本守则不是凭空制定的偏好，而是两次真实交付的结论：

- **V1.20.1（加法失败案例）**：一次性向首页加入知识检索 / 知识资产 / 快捷入口 / 学习建议等
  6 块平台视角内容，首页 HTML 体积涨至 43,885 B、9 个 `<section>`。
  结果：**信息量过大，「管理员视角」的陈列弱化了首页最核心的「继续学习」**。
- **V1.20.2（减法修正）**：删除 5 块、迁移 1 块、Hero 瘦身，首页回落到 4 块 / 21,146 B（**−52%**）。
  这是**对上一版方向的正面对回退**，而非修补。

结论：在本产品上，「加法」的边际收益已被证明为负。**默认答案永远是「不加」。**
