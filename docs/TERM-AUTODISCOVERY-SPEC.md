# 术语自动发现（Term Auto-Discovery）— 链路规范

> 版本：**V1.20.6**　｜　入口：**术语库 `/glossary` → 「术语审核」页签**
> 定位：把「语料里已经出现、但术语库还没收录」的专业术语自动找出来，形成待审核队列，
> 由人工逐条裁决后落库。**不新增独立导航模块。**
> 分工原则（Lu 定稿）：**系统负责发现，AI 负责内容。**

---

## 1. 为什么是「恢复 + 换落点」而不是从零做

同一逻辑在 V1.14.0 做过一版（`src/lib/missing-terms.ts`，「待补充术语池扫描」），
随「知识工坊」于 V1.15.2 随导航重构下线。**但数据层与导入链路当时被刻意保留**：

```
content/glossary/imported.json  →  npm run gen:glossary  →  src/data/glossary/imported.ts
                                                            →  GLOSSARY_TERMS（列表 / 详情 / 正文标注 / 检索）
```

V1.20.5 的做法是**恢复被删的扫描逻辑 + 把落点搬到术语库页签**。
V1.20.6 在其上做四件收敛（见 §8 变更记录）。

## 2. 数据链路

```
                ┌──────────────────────────────────────────────────┐
                │ 语料（唯一真相源）                                │
                │  · 课程  src/data/lessons.ts / electives-*.ts     │
                │         / lessons-cams.ts                         │
                │  · 案例  content/cases/*.md                       │
                └───────────────────────┬──────────────────────────┘
                                        │ 构建期（prebuild）
                                        ▼
   scripts/scan-term-candidates.mjs ── 经 scripts/lib/ts-loader.mjs 直载项目 TS 源码
                                        │  · 用 annotateSegments() 挖空已识别术语
                                        │  · 只在未识别区间抽取候选（三档置信度）
                                        │  · 顺带取回正文自带的中文名 / 英文全称 + 课程 id
                                        │  · 与既有产物合并，保留 firstSeenAt
                                        ▼
                    content/glossary/candidates.json   ← 提交进仓库的产物
                                        │ 服务端读取（node:fs）
                                        ▼
   src/app/glossary/page.tsx ──▶ GlossaryTabs ──▶ TermReviewPanel（"use client"）
                                                      │ 采纳 / 忽略（三态分段）
                                                      ▼
                                        localStorage（只存归一 key）
                                                      │ 采纳后导出
                                                      ▼
                    「术语补全包」＝ 已填真值 + 〔待补〕占位 + imported.json 骨架
                                                      ▼
                                        Copilot 撰写内容类字段 → imported.json
                                                      ▼
              npm run gen:glossary  →  src/data/glossary/imported.ts
                                                      ▼
              npm run check:glossary（闸门：导入 ≈ 内置，同一套六项校验）
                                                      ▼
                                                    全站生效
```

> ⚠️ **prebuild 顺序**：`gen:cases → gen:glossary → **check:glossary** → scan:terms`。
> 闸门改为直载数据层后（V1.20.6），`gen:glossary` **必须**排在 `check:glossary` 之前，
> 否则校验的是上一版烘焙产物。

## 3. 三档置信度（扫描器按此顺序排序）

| 档 | 判定 | 实测表现 |
|---|---|---|
| `declared` 正文声明 | 正文自带「中文名（缩写）」或「缩写（英文全称）」 | 精度最高 |
| `acronym` 缩写 | 中文语境中的 2~6 位全大写缩写 | 精度高 |
| `phrase` 词组 | 中文语境中的首字母大写词组（1~3 词） | 含人名 / 通用词误报，需人工判断 |

**默认只看前两档**（「高置信」，V1.20.6）：审核队列先清高置信，词组档按需切到「词组 / 全部」查看。

### 关键过滤规则

1. **已识别片段挖空** —— 用与页面标注**完全相同**的术语引擎 `annotateSegments()`，
   所以术语库里已有的词不会重新冒出来（口径不可能漂移）。
2. **「中文语境」规则（最有效的一条）** —— 候选词 ±30 字符窗口内必须出现 CJK 字符。
   中文夹英文才叫术语；整段英文（客户邮件、英文 SOP 引用、双语段落）里的 `Kindly` /
   `Verify` / `Please` 由此被整类滤掉。
3. **占位符** —— 连续字母串（`ABC` / `DEF` / `ABCD`）、重复字母（`AA`）、`XYZ`。
4. **地名 / 货币缩写** —— `HK` / `US` / `EU` / `USD` / `HKD` …
5. **公司后缀** —— 以 `…Ltd` / `…Limited` / `…Pte` 结尾的判为案例虚构主体。
6. **停用词与项目噪声** —— 模板词、通用动作词、邮件用语，以及本项目专有噪声
   （`PROJECT_NOISE`，如机构名缩写）。新增噪声词直接改这两处数组。

> ⚠️ **边界：只发现英文与缩写，中文术语不做自动发现。**
> 中文专业词没有词典兜底，靠形态规则抽取误报率不可控，宁可漏也不脏。

### 顺带取回（V1.20.6）

声明档会把正文自带的信息一并带回候选，作为**补全包的真实值**（零臆造）：

| 字段 | 来源 | 可靠性 |
|---|---|---|
| `fullName` | `缩写（英文全称）` 的括号内 | 高（形态明确） |
| `zh` | `中文名（缩写）` 的括号**之前** | 中（可能带前缀噪声，如「提交可疑活动报告」；补全包内已标注需校验） |
| `courseIds` | 语料来源的课程 id（`"02"` / `"E04"`） | 高 |

抽取规则刻意**只剥虚词与状语**（另行 / 单独 / 应当 / 的 …），不剥实义动词 ——
「登记机构」「报告主体」「披露义务」这类真实中文名以动词性字眼开头，剥了反而更错。

## 4. 文件职责

| 文件 | 角色 | 备注 |
|---|---|---|
| `scripts/scan-term-candidates.mjs` | 扫描器（prebuild） | 非阻断：失败只告警，保留上一次产物 |
| `scripts/lib/ts-loader.mjs` | 让 Node 直载项目 TS 源码 | 依赖 Node ≥ 22.18 的类型剥离；**不用正则解析 TS**，避免口径漂移 |
| `scripts/check-glossary.mjs` | **术语闸门**（prebuild，失败阻断构建） | V1.20.6 起直载 `GLOSSARY_TERMS`，导入与内置同标准 |
| `scripts/build-glossary-import.mjs` | `imported.json` → `imported.ts` 烘焙 | 缺项跳过 + 占位符拒收，保证半成品不入库 |
| `content/glossary/candidates.json` | **构建产物（提交进仓库）** | 同 `content/cases/index.json` 模式 |
| `src/types/term-candidates.ts` | 类型 + 置信度枚举 | 零依赖，客户端可安全 import |
| `src/lib/term-candidates.ts` | 候选池读取 | ⚠️ **服务端专用（node:fs），禁止客户端 import** |
| `src/lib/term-review-store.ts` | 本机审核状态 + 补全包拼装 | 独立 key `fund-admin-academy-term-review-v1` |
| `src/components/glossary/TermReviewPanel.tsx` | 审核面板 | 仅在点开页签后挂载 |

## 5. 维护动作

审核面板分**三态**（V1.20.6，互斥）：**待审核 / 已采纳 / 已忽略**。

| 动作 | 语义 |
|---|---|
| **导入术语库** | 采纳该候选 → 移入「已采纳」分段。**不会立刻进术语库**（静态站浏览器写不了源码） |
| **生成术语补全包** | 把已采纳术语拼成**结构化半成品**：系统填好可确定字段，待撰写字段标 `〔待补〕`，末尾附可直接落库的 `imported.json` 骨架 |
| **忽略** | 本机记录归一 key，移入「已忽略」分段；可随时恢复 |
| **看上下文** | 展开该术语在语料中的原文摘录（可点进来源课程 / 案例） |

> 三态**互斥**：待审核 = 候选池 − 已忽略 − 已采纳。
> 已采纳 / 已忽略分段会保留**已从候选池消失**的历史 key（可追溯），这类条目在列表里标注「已不在候选池」。

### 补全包里的职责分界（V1.20.6）

| 谁填 | 字段 |
|---|---|
| **系统预填（零臆造）** | `id` / `term` / `zh` / `fullName`（正文自带时）/ `courses` / `cases` |
| **Copilot 撰写** | `definition` / `whyImportant` / `commonMistakes` / `brief` / `category` / `level` / `jurisdiction` / `scenario` / `aliases` / `related` / `source` / `tags` |

补全包内附带：受控枚举全清单、`related` 指向约束、「不写时效性内容」硬规矩、
「不属于本领域请剔除并说明理由」的要求。

## 6. 硬约束

- **系统负责发现，AI 负责内容**（V1.20.6 定稿）：审核页只做发现 / 审核 / 采纳 / 忽略 / 导出，
  **不在站内生成或编辑术语正文** —— 避免出现两个内容来源（后续同步与覆盖风险）。
  因此**不接入任何模型能力**，模型调用与内容生产留在 Copilot 侧。
- **导入 ≈ 内置**（V1.20.6）：术语闸门直载 `GLOSSARY_TERMS`（内置 ∪ 导入），
  六项检查（重复 id / 断链 / 案例引用 / 课程引用 / 标注撞车 / 必填字段）对导入条目**一视同仁**。
  这是**结构性保证**，不再依赖「记得同步改两处」。
- **占位符防呆**（V1.20.6）：`imported.json` 中任何字段值含 `〔待补〕` → 该条**拒收并告警**。
  与闸门形成双保险（`related` 未替换还会被断链校验拦下）。
- **幂等写盘**：候选内容签名未变时复用 `firstSeenAt` / `lastSeenAt` / `generatedAt`，
  `candidates.json` 逐字节稳定 —— 跑多少次构建都不会污染 git 工作区（有验证）。
- **非阻断**：TS loader 注册失败（Node < 22.18）/ 源码加载失败 / 扫描抛错 → 只告警 + 保留旧产物，**绝不拦构建**。
  （注意：**闸门 `check:glossary` 是阻断式的**，两者定位不同。）
- **首帧安全**：审核面板只在用户点开页签后挂载，故可惰性读 localStorage。
  ⚠️ 若日后把它改成**默认页签**，必须改成「首帧恒默认态 + 挂载后回读」，否则会引发 React #418。
- **本机状态只存 key**，不存候选正文 —— 候选池重扫后内容自动更新，不会留旧副本造成前后不一致。
- **不收录时效性内容**（生效日期 / 罚款 / 执法数字）；标准答案类内容必须依据 ICS SOP。
- **审核页不重复展示已有信息**（Subtraction First）：不重复术语列表、不放统计卡
  （数字已在分段徽标与置信 chip 上）；「已发布术语」视图已于 V1.20.6 删除。

## 7. 已知边界（后续可议）

1. ~~`check-glossary.mjs` 不校验 `imported.ts`~~ → **V1.20.6 已收口**（闸门直载数据层）。
2. ~~「已发布术语」视图与术语列表 / Dashboard 信息重叠~~ → **V1.20.6 已删**（Subtraction First）。
3. 词组档精度约六成，尚无更好的收紧手段（收紧会误杀只出现一次的真术语）。
4. `zh` 自动提取在前缀较复杂时可能残留噪声（如「提交可疑活动报告」），
   补全包内已显式标注需人工校验；不追求自动改写（易过度纠正）。
